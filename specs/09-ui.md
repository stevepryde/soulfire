# UI

**Purpose:** define the screen flow, navigation, app shell, theme system, design tokens, and the
visual/interaction contract the client must honor to reproduce Soulfire-OG's look and feel on desktop
and mobile. Per-feature behavior lives in `CHAT`/`CHAR`/`WORLD`/`IMG`/`PROMPT`/`STAT`/`ONB`; this spec
owns the surface.

## Requirements

### Theme & tokens
- **UI-1** The app is **dark-only**. The single user-tunable theme dimension is an **accent color**,
  chosen from seven options: Purple (default), Blue, Green, Red, Orange, Teal, Grey. The choice
  persists (`DATA-18`) and recolors the brand wordmark, primary controls, spinners, and accents
  app-wide.
- **UI-2** The design tokens reproduce Soulfire-OG: a dark background/surface palette, the accent
  `--color-primary*` ramp per theme, functional colors (link teal, error pink), the Inter sans UI
  font, and the **Merriweather serif** used for narrative/story text (adventure narration, world
  intros, empty-state hero lines). Typography scale, spacing, and container widths follow
  Soulfire-OG's scale.
- **UI-3** The app honors mobile constraints: a minimum 44px touch target for interactive elements,
  no horizontal scrolling at small widths, safe-area handling for notches/gesture bars, and
  contained overscroll (no pull-to-refresh). Layouts are responsive across phone, tablet, and desktop
  widths.

### App shell & navigation
- **UI-4** Two surface idioms, reproduced from Soulfire-OG: **standard pages** (worlds home,
  characters, settings, profile, editors) render a full-bleed dark page with a top accent gradient and
  blur accents, a fixed top **title bar**, and constrained-width content; **immersive pages** (play,
  chat, first-run) hide all chrome and use a themed or world-image backdrop with a floating glassy
  header pill and a glassy input composer.
- **UI-5** The **title bar** (standard pages) shows the round app logo (to home), the centered
  "Soulfire" brand wordmark, and a profile avatar (to the profile screen). A small connection/activity
  indicator dot reflects AI/streaming status (idle/working/ready) on the relevant surfaces.
- **UI-6** Primary navigation has three destinations: **Worlds**, **Characters** (which contains
  chats), and **Settings**. On desktop these appear as a left sidebar; on mobile as a bottom
  navigation bar. The active destination is indicated. Soulfire-OG's account/admin/billing nav is
  removed (`PROD-11`).
- **UI-7** A reusable **confirmation dialog** gates destructive actions (delete chat/character/world/
  adventure), optionally requiring the user to type a confirmation word for high-risk deletes, with a
  danger styling for the confirm button. A reusable **info modal** presents tips/help.

### Worlds home
- **UI-8** The worlds home is the default landing surface for returning users (`ONB`), with tabs:
  **Adventures** (continue/in-progress playthroughs) and **Worlds** (discover/start). When world
  creation is available, a **My Worlds** tab lists the user's blueprints with Builder / Edit / Enter
  actions and create entries (Manual and World Builder). Each tab has search and incremental loading,
  skeleton loaders, and a consistent empty state. (Soulfire-OG's public/admin worlds tabs are
  removed.)
- **UI-9** Adventure and world cards reproduce Soulfire-OG: a 16:6 cover (generated image or accent
  gradient + emoji), title, clamped description, optional metadata, an overflow menu (delete, and for
  worlds regenerate-image), a "Completed" indicator where applicable, and a primary action ("Continue
  Adventure" / "Enter World").

### Play (adventure) screen
- **UI-10** The play screen is immersive (`UI-4`): a world-image or themed backdrop with faint
  emoji watermarks, a floating header pill (back, world title, and contextual chips — "NPC" to extract
  a character once the adventure has progressed, "Rate" is **removed** with ratings, `PROD-11`), a
  scrollable message panel, and a glassy composer.
- **UI-11** Message rendering by type: **narration** as large serif prose (no bubble); **player
  action** as a right-aligned bubble labeled "YOU"; **GM request** as a right-aligned accent bubble;
  **GM response** as a left bubble — and when a GM response is a staged change proposal, it renders
  the proposal with a before/after **diff list** and **Accept/Reject** controls, showing an
  Accepted/Rejected state after decision (`WORLD-17`). A working indicator (themed typing animation)
  shows while a turn is in progress; an end banner shows on success/failure (`WORLD-6`).
- **UI-12** The composer shows a status line that reflects turn state ("What do you do?", "Consulting
  game master…", "Updating adventure state…", etc.), an auto-growing action input, and a send button
  that disables while a turn is in progress or input is empty. Input starting with `/gm ` is a
  game-master command; other slash inputs warn (`WORLD-15`). The in-progress action draft is persisted
  locally per adventure and restored on return.
- **UI-13** A world **intro/loading** state shows the world's emoji, its description in large serif,
  and its title, as the atmospheric opening (`ONB`), before the first narration appears.

### Chat screen
- **UI-14** The chat screen is immersive (`UI-4`), mirroring the play screen's visual language: a
  themed backdrop, a floating header pill with back, the character name, and the character avatar; a
  scrollable message list (constrained width); and a glassy composer with an auto-growing input and a
  send button that disables while waiting or input is empty. The in-progress message draft is
  persisted locally per chat.
- **UI-15** Chat messages render as left/right bubbles (character/player) with sender label and time,
  message text rendered as lightweight markdown, emoji reactions shown under the bubble, a per-message
  context action (copy text), and a long-press/right-click **emoji picker** limited to the allowed set
  (`DATA-6`). A themed spinner/typing indicator reflects connecting vs waiting vs ready (`CHAT`).
- **UI-16** Streamed replies render token-by-token as they arrive (`AI-10`, `CHAT-4`).

### Characters & chats lists
- **UI-17** The characters surface lists saved characters (avatar, name, origin/subtitle, description,
  last-chat time) with search, incremental loading, and row actions (open/continue chat, edit,
  regenerate image, delete chat, delete character), plus entries for "New Character" and "Character
  Builder" (`CHAR-13`). Tapping a row opens the existing chat or starts a new one.

### Editors & builders
- **UI-18** The manual editors (character, world) use a tabbed header (underline-active tabs) over a
  full-bleed dark page with a back action, a title, a primary Save action, and a cross-link to the
  corresponding **builder** (and back). Builder screens present a Chat tab (message bubbles + typing
  indicator + composer) and an inspect tab (current prompt/blueprint), plus an **Undo** action that is
  disabled when no snapshots exist (`CHAR-6..9`, `WORLD-20..21`).
- **UI-19** Emoji avatar/cover selection opens a searchable emoji grid; when a generated/uploaded
  image exists, the corresponding crop/transform editor is shown (`IMG-7`).

### Settings & profile
- **UI-20** **Settings** contains: **Appearance** (accent color selector showing all seven options);
  **AI** (the curated default-model selector, `AI-7`; and the **API key** entry — masked, `SEC-10`);
  **Content** (the prompt toggles incl. **Adult content**, `PROMPT-6`); **Adventure Defaults** (the
  PlayerProfile: player name, attributes, optional prompt extension, `DATA-17`); and entry to **Token
  Statistics** (`STAT`) and **Security** (lock, change master password, remember-on-device, `SEC-8`).
- **UI-21** **Profile** shows the app profile (avatar, name/nickname, language) and lets the user edit
  it. Soulfire-OG's account/email/admin/billing/logout/delete-account items are removed; a local
  "lock app" action takes their place (`SEC-8`). The prompt **viewer/editor** (`PROMPT-9`) is reachable
  from a character or adventure.

### Status, errors, drafts
- **UI-22** Loading uses skeletons/spinners; errors use a consistent status surface with a clear
  message and, where applicable, a retry; a missing-API-key condition routes the user to add a key
  (`AI-3`). Lists paginate incrementally with a "load more" affordance and consistent empty states.
- **UI-23** A launch/lock screen (`SEC-5`) precedes the app on each cold start until unlocked; a
  brief splash may precede it.

## Acceptance criteria

- **AC-UI-a** (UI-1) Changing the accent color recolors the wordmark, primary buttons, and spinners
  across all screens and persists across restart.
- **AC-UI-b** (UI-3) At 320px width no screen scrolls horizontally and interactive targets meet 44px;
  pull-to-refresh is suppressed.
- **AC-UI-c** (UI-4, UI-6) Standard pages show the title bar and the three-destination nav (sidebar on
  desktop, bottom bar on mobile); play/chat/first-run hide all chrome.
- **AC-UI-d** (UI-11, UI-12) In an adventure, the four message types render distinctly, a `/gm` change
  renders an accept/reject diff, the composer status reflects turn state, and the action draft
  survives leaving and returning.
- **AC-UI-e** (UI-15, UI-16) Chat bubbles render markdown and reactions, the emoji picker is limited to
  the allowed set, and replies stream token-by-token.
- **AC-UI-f** (UI-20, UI-21) Settings exposes appearance, model, masked API key, content toggles,
  adventure defaults, token stats, and security; profile has no account/billing/admin items.
- **AC-UI-g** (UI-7) Deleting a character requires confirmation; high-risk deletes require typing a
  confirmation word.

## Design notes (non-normative)

- Built with Dioxus (desktop/mobile) reusing Soulfire-OG's component structure (`components/`,
  `pages/`, `hooks/theme.rs`, `input.css`) and Lucide icons. The reference is web/CSR + Tailwind v4;
  the rebuild keeps the styling approach so RSX and classes port closely. Replace web-only mechanics
  (service worker, websocket providers, `wasm_bindgen` event glue) with desktop/mobile equivalents;
  the Soulfire-OG websocket-driven chat/adventure providers become in-process service providers
  feeding the same UI state (`CHAT`/`WORLD`).
- The exact token values, per-theme `--primary-*` ramps, named CSS utility classes (wordmark,
  glass/card/composer treatments, spinner/typing animations), and component props are carried from
  Soulfire-OG `input.css` and `components/` as the implementation reference.
- Removed surfaces to delete entirely: landing/auth/login/MFA, billing/subscribe, admin (stats,
  analytics, metrics, AI-eval, users, moderation), public/all-worlds tabs, ratings, and the
  daily-limit popup's upgrade path (`PROD-11`). The daily-limit popup is removed; provider quota
  errors surface via the normal error surface (`AI-12`).
